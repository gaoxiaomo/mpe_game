## 3. 3.3 多对多危险交叉场景结果

这一节建议采用“2D 简化验证 + 6v3 真实场景验证”的结构。

### 3.3.1 简化 2D 交叉场景

建议放图：
- [fig_2d_trajectory_compare.png](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/collision_demo_rigorous_final/reduced_2d/fig_2d_trajectory_compare.png)
- [fig_2d_dmin_compare.png](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/collision_demo_rigorous_final/reduced_2d/fig_2d_dmin_compare.png)

建议说明：
- 这一部分用来直观展示“解析项会提前组织换道路径”的基本思路。
- 重点不是说明真实飞行器性能，而是先在最简单的交叉几何中验证机制。
- 可直接写结果：
  - `d_safe = 500 m`
  - 无解析项：`min d_min = 0.039 m`，危险带内停留 `15.6 s`
  - 平滑解析项：`min d_min = 1743.04 m`，危险带内停留 `0.0 s`

### 3.3.2 6v3 真实多对多危险交叉场景

建议放图：
- [fig_xy_compare.png](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/many_to_many_collision_6v3_final/fig_xy_compare.png)
- [fig_dmin_compare.png](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/many_to_many_collision_6v3_final/fig_dmin_compare.png)

可选答辩动图：
- [no_analytic/fig_trajectory_3d.gif](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/many_to_many_collision_6v3_final/no_analytic/fig_trajectory_3d.gif)
- [smooth_analytic/fig_trajectory_3d.gif](E:/mpe_game/mpe_game/repro_vsnac_mpe_comm/outputs/many_to_many_collision_6v3_final/smooth_analytic/fig_trajectory_3d.gif)

建议说明：
- 这一部分是“真实场景主验证”，重点说明解析项在六自由度多对多追逃中仍然有效。
- 场景设置为 `d_safe = 50 m`。
- 建议强调：
  - 无解析项：最小组内间距 `0.995 m`，危险带内停留 `1.5 s`
  - 平滑解析项：最小组内间距 `82.404 m`，危险带内停留 `0.0 s`
- 终端相对位移偏差不再直接用米数，而采用“占名义相对位移尺度的比例”。
- 对于 6v3 构造场景，比例建议使用延长到 `160 s` 的评估时域统计：
  - 无解析项：`0.09%`
  - 平滑解析项：`0.31%`
- 这样能更公平地说明：解析项在危险交叉阶段优先保证安全，但在较长时域下仍能回到与无解析项同量级的名义相对位形附近。

推荐正文表格列：
- 最小组内间距/m
- 危险带内停留时间/s
- 最长连续危险时段/s
- 终端相对位移偏差占比/%
- 稳定捕获时间/s

推荐这一节的主结论：
- 解析项并不是简单地“把所有人推远”，而是在高风险阶段主动调整同组追逐者的相对速度、相对位形和换道路径。
- 它能够显著提高最小间距，并把危险带停留时间压到 0。
- 在较长时域下，终端相对位移偏差占比仍保持很小，说明安全收益不是以完全破坏围捕几何为代价获得的。
